# Next.js Event-Driven System (Pub/Sub + EventEmitter) — Complete Note

---

# 1. What is Event-Driven Architecture ?

Event-driven architecture is a system where:

```txt id="e1"
One action (Event) triggers multiple independent reactions (Listeners)
```

---

## Example Concept:

```txt id="e2"
User Created Event
   │
   ├── Send Email
   ├── Log Activity
   ├── Add Analytics
   └── Trigger Notification
```

---

# 2. What is Pub/Sub ?

Pub/Sub = Publisher / Subscriber model

```txt id="e3"
Publisher → emits event
Subscribers → listen & react
```

---

## Flow:

```txt id="e4"
Publisher (emit event)
        │
        ▼
     Event Bus
        │
 ┌──────┼────────┐
 ▼      ▼        ▼
Listener Listener Listener
```

---

# 3. Why use Event System in Next.js ?

```txt id="e5"
✔ Decouple logic
✔ Avoid spaghetti code
✔ Scale background features
✔ Easy feature extension
```

# 9. Publisher (Emit Event)

## services/userService.js

```js id="e11"
import { eventBus } from "../lib/eventBus.js";
import { USER_CREATED } from "../events/userEvents.js";

export async function createUser(user) {

    // simulate DB save
    const savedUser = {
        id: Date.now(),
        ...user,
    };

    console.log("User saved in DB");

    // PUBLISH EVENT
    eventBus.emit(USER_CREATED, savedUser);

    return savedUser;
}
```

# 10. Subscriber 1 → Email Service

## events/listeners/emailListener.js

```js id="e12"
import { eventBus } from "../../lib/eventBus.js";
import { USER_CREATED } from "../userEvents.js";

eventBus.on(USER_CREATED, (user) => {

    console.log("EMAIL Listener Triggered");

    sendWelcomeEmail(user.email);
});

function sendWelcomeEmail(email) {

    console.log("Sending email to:", email);
}
```

# 20. Important Limitation

```txt id="e22"
EventEmitter is NOT persistent
```

Meaning:

```txt id="e23"
If server restarts → all events are lost
```

---

# 21. Production Upgrade (Important)

For real systems:

```txt id="e24"
EventEmitter → Redis Pub/Sub → Kafka (advanced)
```

---

# 22. When NOT to use EventEmitter

```txt id="e25"
❌ Critical financial transactions
❌ Required persistence workflows
❌ Multi-server systems without Redis
```

---

# 23. When to use EventEmitter

```txt id="e26"
✔ Notifications
✔ Logging
✔ Analytics
✔ Internal decoupling
```
