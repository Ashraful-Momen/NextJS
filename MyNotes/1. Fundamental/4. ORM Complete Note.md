3️⃣ Prisma Relationship Basics
==============================

? Meaning
===========

Optional relation / nullable field.

    profile Profile?
    

Meaning:

   User may have profile
   User may NOT have profile

Equivalent SQL:

    profileid NULL
    

  

[] Meaning
============

Array relation / multiple rows.

    posts Post[]
    

Meaning:

   One user has many posts

  

No ?
======

Required relation.

    user User
    

Meaning:

   This relation is mandatory
   Cannot be NULL

  

4️⃣ One-to-One (1:1)
====================

User ↔ Profile
==============

Schema
------

    model User {
      id       Int       @id @default(autoincrement())
      email    String    @unique
    
      profile  Profile?
    }
    
    model Profile {
      id       Int       @id @default(autoincrement())
      bio      String?
    
      userId   Int       @unique
    
      user     User      @relation(fields: [userId], references: [id])
    }
    

  

Why @unique?
==============

    userId Int @unique
    

Ensures:

   One profile per user
   Prevents duplicate profile rows

  

Create
======

    await prisma.user.create({
      data: {
        email: "test@gmail.com",
    
        profile: {
          create: {
            bio: "Hello"
          }
        }
      }
    });
    

  

Query
=====

    await prisma.user.findUnique({
      where: {
        id: 1
      },
    
      include: {
        profile: true
      }
    });
    

  

5️⃣ One-to-Many (1:M)
=====================

User ↔ Posts
============

Schema
------

    model User {
      id      Int      @id @default(autoincrement())
      email   String   @unique
    
      posts   Post[]
    }
    
    model Post {
      id      Int      @id @default(autoincrement())
      title   String
    
      userId  Int
    
      user    User     @relation(fields: [userId], references: [id])
    }
    

  

Why Post[]?
=============

    posts Post[]
    

Means:

   Multiple posts belong to one user

  

Create Post
===========

    await prisma.post.create({
      data: {
        title: "My Post",
    
        user: {
          connect: {
            id: 1
          }
        }
      }
    });
    

  

Query User Posts
================

    await prisma.user.findUnique({
      where: {
        id: 1
      },
    
      include: {
        posts: true
      }
    });
    

  

6️⃣ Many-to-Many (M:M)
======================

Automatic Pivot Table
=====================

Post ↔ Tags
===========

Prisma automatically creates pivot table internally.

You DO NOT create pivot table manually.

  

Schema
======

    model Post {
      id     Int      @id @default(autoincrement())
      title  String
    
      tags   Tag[]    @relation("PostTags")
    }
    
    model Tag {
      id     Int      @id @default(autoincrement())
      name   String   @unique
    
      posts  Post[]   @relation("PostTags")
    }
    

  

Why [] Both Sides?
====================

    tags Tag[]
    posts Post[]
    

Means:

   One post → many tags
   One tag → many posts

  

Create
======

    await prisma.post.create({
      data: {
        title: "Next.js Guide",
    
        tags: {
          connectOrCreate: [
            {
              where: {
                name: "nextjs"
              },
    
              create: {
                name: "nextjs"
              }
            }
          ]
        }
      }
    });
    

  

Query
=====

    await prisma.post.findUnique({
      where: {
        id: 1
      },
    
      include: {
        tags: true
      }
    });
    

  

7️⃣ Many-to-Many With Custom Pivot Table
========================================

User ↔ Courses
==============

Used when pivot table needs extra columns.

Example:

   progress
   status
   enrolledAt

  

Schema
======

    model User {
      id        Int            @id @default(autoincrement())
      email     String         @unique
    
      courses   UserCourse[]
    }
    
    model Course {
      id        Int            @id @default(autoincrement())
      title     String
    
      users     UserCourse[]
    }
    
    model UserCourse {
      userId    Int
      courseId  Int
    
      progress  Int            @default(0)
      status    String         @default("pending")
    
      user      User           @relation(fields: [userId], references: [id])
      course    Course         @relation(fields: [courseId], references: [id])
    
      @@id([userId, courseId])
    }
    

  

Why Custom Pivot Table?
=======================

Because automatic M:M cannot store extra fields.

This custom pivot allows:

    userId
    courseId
    progress
    status
    createdAt
    updatedAt
    

  

Add User To Course
==================

    await prisma.userCourse.create({
      data: {
        userId: 1,
        courseId: 2,
    
        progress: 20,
        status: "active"
      }
    });
    

  

Query
=====

    await prisma.user.findUnique({
      where: {
        id: 1
      },
    
      include: {
        courses: {
          include: {
            course: true
          }
        }
      }
    });

    }
    

  

NOT IN

    }
    

  

NULL

NOT NULL

2️⃣3️⃣ Production Best Practices
================================

Add timestamps
==============

    createdAt DateTime @default(now())
    updatedAt DateTime @updatedAt
    

  

Add indexes
===========

    @@index([email])
    

  

Use enum
========

    enum Role {
      ADMIN
     USER
    }
    

  

Add cascade delete carefully
============================

    @relation(
      fields: [userId],
      references: [id],
      onDelete: Cascade
    )
    

  

🚀 Final Daily Query Pattern
============================

    const data = await prisma.user.findMany({
      where: {
        deletedAt: null
      },
    
      include: {
        role: true
      },
    
      orderBy: {
        id: "desc"
      },
    
      skip: 0,
    
      take: 10
    });
    

This single pattern covers most production CRUD APIs.
