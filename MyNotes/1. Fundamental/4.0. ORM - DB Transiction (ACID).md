# Next.js Database Transaction Note (PostgreSQL)

## 1. What is a Database Transaction?

A database transaction is a way to execute multiple database operations as a single unit of work.

Transactions ensure:
* All queries succeed together
* Or all queries fail together
* No partial data is saved
* Data consistency remains safe

---

## 2. The Two Transaction Types

```txt
┌────────────────────────────────────────────────────────┐
│               PostgreSQL Transactions                  │
└────────────────────────────────────────────────────────┘
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
 ┌───────────────────────┐   ┌───────────────────────┐
 │       Automatic       │   │        Manual         │
 │     (Prisma ORM)      │   │     (Raw Driver)      │
 └───────────────────────┘   └───────────────────────┘
             │                           │
     Auto-handles State          Explicit Management
     Commit on Success           BEGIN / COMMIT
     Rollback on Error           ROLLBACK on Error
```

## 3. Automatic Transactions (Prisma ORM)

Prisma uses a closure block. It manages connection lifecycles automatically.

### app/actions/dbActions.js

```javascript
import { prisma } from "@/lib/prisma";

export async function updateStatus(id) {
  try {
    return await prisma.\$transaction(async (tx) => {
      
      // 1. First operation (Update User)
      const user = await tx.user.update({
        where: { id },
        data: { status: "active" }
      });
      
      // 2. Add other queries using 'tx' here if needed...
      
      return { success: true, user }; 
      // <-- SUCCESS: Prisma automatically calls COMMIT here
    });
  } catch (error) {
    // <-- FAILURE: Prisma automatically calls ROLLBACK here
    return { success: false, error: error.message };
  }
}
```

## 4. Automatic Transaction Flow

```txt
Start \$transaction Block
           │
           ▼
   Run Query 1 (tx)
           │
           ├── Any Error Found?
           │       ▼
           │   Auto ROLLBACK Database
           │
           └── All Queries Clean?
                   ▼
               Auto COMMIT Database
```

## 5. Manual Transactions (Raw pg Driver)

If you require literal step-by-step control, utilize the standard native PostgreSQL driver.

### app/actions/dbActionsManual.js

```javascript
import { Pool } from "pg";

const pool = new Pool(); // Configured via process.env variables

export async function updateStatusManual(id) {
  const client = await pool.connect();
  
  try {
    // 1. Explicitly open transaction
    await client.query("BEGIN");

    // 2. Execute target row update
    const queryStr = "UPDATE users SET status = 'active' WHERE id = \$1";
    await client.query(queryStr, [id]);

    // 3. Explicitly finalize changes
    await client.query("COMMIT");
    return { success: true };

  } catch (error) {
    // 4. Explicitly undo modifications on error
    await client.query("ROLLBACK");
    return { success: false, error: error.message };

  } finally {
    // 5. Always free connection thread back to pool
    client.release();
  }
}
```

---

## 6. Manual Transaction Flow

```txt
Get Client From Pool
        │
        ▼
   Run "BEGIN"
        │
        ▼
   Run SQL Query
        │
        ├── Catch Error Block
        │       ▼
        │  Run "ROLLBACK"
        │
        └── Clean Completion Block
                ▼
           Run "COMMIT"
                │
                ▼
         Release Client
```

## 7. Method Comparison Summary


| Feature | Prisma (Automatic) | pg Driver (Manual) |
| :--- | :--- | :--- |
| **Command Syntax** | Safe JavaScript Objects | Raw SQL Strings ($1 variables) |
| **Commit Trigger** | Implicitly at final `}` bracket | Explicitly via `client.query('COMMIT')` |
| **Rollback Trigger** | Implicitly on code throw | Explicitly via `client.query('ROLLBACK')` |
| **Connection Closing**| Automatic handling | Manual handling via `client.release()` |

## 8. Forcing Manual Rollback in Prisma

To undo database writes conditionally inside an automatic closure, throw a standard error block.

```javascript
await prisma.\$transaction(async (tx) => {
  const user = await tx.user.update({
    where: { id },
    data: { status: "active" }
  });

  if (user.isBlocked) {
    // THROWING AN ERROR FAILS THE BLOCK AND TRIGGERS AUTO-ROLLBACK
    throw new Error("Cannot activate a blocked user profile");
  }
});
```

## 9. Critical Execution Rules

### Always Use Scoped Client (tx)

Inside Prisma `$transaction`, execute operations through the block variable placeholder argument (`tx`), **not** the global server `prisma` connection instance.

```javascript
// ❌ WRONG (Runs outside transaction line)
await prisma.user.update(...);

//  RIGHT (Safely bound to transaction thread)
await tx.user.update(...);
```

### Connection Cleanup Requirement

When dealing with manual configurations via raw drivers (`pg`), running `.release()` inside a structural `finally {}` block is mandatory. Neglecting this freezes available slots inside your connection pools.
