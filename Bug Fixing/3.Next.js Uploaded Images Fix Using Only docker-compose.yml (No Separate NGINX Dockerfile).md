# Complete Note — Next.js Uploaded Images Fix Using Only docker-compose.yml (No Separate NGINX Dockerfile)

# Problem Overview

After building a Next.js app:

```bash id="g8m8lz"
npm run build
npm start
```

admin uploads new product images but images do not show.

Example:

```txt id="b7tx2q"
Admin Uploads:
cow.jpg

Saved Successfully

But Browser Shows:
404 Not Found
```

---

# Why This Happens

Next.js production build is optimized for:

* Static assets
* Build-time files
* Frontend rendering

But uploaded images are:

```txt id="l9n1om"
Runtime Dynamic Files
```

Meaning:

```txt id="hsm2ur"
Files are created AFTER deployment
```

Next.js does not efficiently serve these runtime uploaded files in production.

Especially inside Docker containers.

---

# Correct Production Solution

Use:

```txt id="rcrfh0"
NGINX as Separate Static File Server
```

NGINX will:

* Serve uploaded images directly
* Bypass Next.js
* Improve performance
* Support caching
* Work perfectly with Docker volumes

# Complete NGINX Config

```nginx id="z6d7hf"
server {

    listen 80;

    server_name smartdairybd.com www.smartdairybd.com;

    return 301 https://$host$request_uri;
}

server {

    listen 443 ssl;

    http2 on;

    server_name smartdairybd.com www.smartdairybd.com;

    ssl_certificate /etc/letsencrypt/live/smartdairybd.com/fullchain.pem;

    ssl_certificate_key /etc/letsencrypt/live/smartdairybd.com/privkey.pem;

    ssl_protocols TLSv1.2 TLSv1.3;

    ssl_ciphers HIGH:!aNULL:!MD5;


    # =====================================
    # Uploaded Images
    # =====================================

    location /images/uploads/ {

        alias /var/www/images/uploads/;

        expires 1y;

        add_header Cache-Control "public, immutable";

        access_log off;

        autoindex off;

        try_files $uri =404;
    }


    # =====================================
    # Next.js App
    # =====================================

    location / {

        proxy_pass http://host.docker.internal:3000;

        proxy_http_version 1.1;

        proxy_set_header Upgrade $http_upgrade;

        proxy_set_header Connection 'upgrade';

        proxy_set_header Host $host;

        proxy_set_header X-Real-IP $remote_addr;

        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_cache_bypass $http_upgrade;
    }
}
```

# Complete docker-compose.yml

```yaml id="9f9f4l"
services:

  postgres:
    image: postgres:15-alpine

    container_name: smart-dairy-db

    restart: unless-stopped

    ports:
      - "127.0.0.1:5433:5432"

    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: JBwReBCp13wcXux9sqMOe0eFoepuVCTk
      POSTGRES_DB: smart_dairy_clone

    volumes:
      - postgres_data:/var/lib/postgresql/data
      - ./scripts/postgres-entrypoint.sh:/usr/local/bin/postgres-entrypoint.sh:ro

    command: ["/usr/local/bin/postgres-entrypoint.sh"]

    security_opt:
      - no-new-privileges:true

    tmpfs:
      - /tmp:noexec,nosuid,size=100m

    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 10s
      timeout: 5s
      retries: 5



  nginx:
    image: nginx:alpine

    container_name: smart-dairy-nginx

    restart: unless-stopped

    ports:
      - "80:80"
      - "443:443"

    volumes:

      # ==========================
      # NGINX Config
      # ==========================
      - ./config/nginx.conf:/etc/nginx/conf.d/default.conf:ro


      # ==========================
      # Uploaded Images
      # ==========================
      - ./public/images/uploads:/var/www/images/uploads:ro


      # ==========================
      # SSL Verification
      # ==========================
      - ./public/.well-known:/var/www/html/.well-known:ro


      # ==========================
      # SSL Certificates
      # ==========================
      - /etc/letsencrypt:/etc/letsencrypt:ro


    extra_hosts:
      - "host.docker.internal:host-gateway"


volumes:
  postgres_data:
```

# Common Problems

| Problem                       | Cause                   |
| ----------------------------- | ----------------------- |
| 404 image                     | Wrong alias path        |
| Permission denied             | Linux folder permission |
| Images not updating           | Browser cache           |
| HTTPS not working             | SSL cert path wrong     |
| Container cannot see files    | Wrong volume mount      |
| Next.js works but image fails | NGINX path mismatch     |
